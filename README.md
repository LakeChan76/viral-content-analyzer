# 爆款内容拆解与二次创作 Agent

> 任务5：发现并筛选高表现内容，拆解爆款逻辑，沉淀可复用模板，生成原创候选内容。

## 一、产品逻辑

### 解决什么问题
内容运营最大的痛点：爆款是玄学。一条爆了不知道为什么爆，下一条扑了不知道为什么扑。复盘全靠感觉，经验无法复用。

### 产品定位
帮内容运营拆解"爆款为什么爆"，找出可复用的规律，再基于规律自动生成新的候选内容。把"凭感觉"变成"有方法论"。

### 用户与场景
- **用户**：X平台内容运营
- **场景**：输入一个X账号 → Agent自动拆解该账号近期高表现内容 → 对比低表现内容 → 输出拆解报告 + 可复用模板 + 3条原创候选内容

### 核心价值
不只是"拆解爆款"（事后总结），而是拆解后能生成可执行的新内容，形成"分析→沉淀→生产→验证"的闭环。

## 二、工作流设计

整条流水线8个环节：

```
输入X账号用户名
    ↓
① 数据采集 — Apify Twitter Scraper自动抓取该账号推文+互动数据（无需登录X、无需API key、基于公开数据源），CSV上传作为兜底
    ↓
② 表现分级 — 按粉丝数算互动率，排序，分TOP5高表现/BOTTOM5低表现
    ↓
③ 爆款拆解 — 大模型从6维度拆解每条高表现内容（选题/Hook/结构/信息密度/CTA/互动设计）
    ↓
④ 驱动因素分析 — 对比高低表现组，找出"高有低无"的驱动因素
    ↓
⑤ 模板沉淀 — 基于驱动因素提炼可复用内容结构模板
    ↓
⑥ 候选内容生成 — 拿模板+主题，生成3条差异化原创内容（英文）
    ↓
⑦ 相似度检查 — 检查候选内容与原文相似度，防抄袭
    ↓
⑧ 人工确认+写入资产库 — 标记"待审核"，人工确认后写入资产库
    ↓
输出：拆解报告 + 内容模板 + 3条候选内容
```

### 闭环：反馈追踪
候选内容发布后，记录实际表现数据 → 用实际表现验证拆解结论准不准 → 如果不准就调整模板。系统不是一次性输出，而是持续进化。

## 四、AI使用方式

Agent在以下4个环节调用大模型，每个环节设计了专用Prompt：

| 环节 | AI做什么 | Prompt设计思路 |
|:---|:---|:---|
| ③ 爆款拆解 | 从6个维度结构化拆解每条高表现推文 | 强制JSON格式输出，确保6个维度全覆盖，便于后续对比 |
| ④ 驱动因素分析 | 对比高低表现组，找出驱动因素 | 提供两组对比数据，要求输出"高有低无"的特征及理由 |
| ⑤ 模板沉淀 | 提炼可复用内容结构模板 | 基于驱动因素，输出结构化模板（开头+主体+结尾的公式） |
| ⑥ 候选内容生成 | 生成3条差异化原创内容 | 套用模板但变换角度/Hook方式，要求英文输出，每条不超过280字符 |

### Prompt设计原则
- **结构化输出**：所有AI输出要求JSON格式，便于程序解析和后续处理
- **Few-shot示例**：关键环节提供示例，引导模型输出符合预期
- **角色设定**：每个Prompt设定专业角色（如"你是资深内容运营专家"），提升输出质量

## 五、人工确认点

⚠️ 按照任务要求"涉及对外发布账号等操作时，必须设置人工确认"。

| 确认点 | 位置 | 确认内容 | 确认方式 |
|:---|:---|:---|:---|
| 候选内容审核 | ⑧写入资产库前 | 人工审核3条候选内容是否可用 | Streamlit界面提供"确认写入"按钮，未点击不写入 |
| 内容修改 | 审核过程中 | 人工可编辑修改候选内容后再写入 | 界面提供文本编辑框，支持修改后确认 |
| 资产库管理 | 写入后 | 查看历史资产、标记已发布/已验证 | 资产库页面支持状态标记 |

### 设计原则
- 候选内容**永远不会自动发布**，只写入待审核资产库
- 人工确认是流程的必经环节，不是可选环节
- 确认界面清晰展示：拆解报告、驱动因素、候选内容、相似度评分，辅助人工决策

## 六、当前局限

1. **数据采集依赖第三方服务**：当前使用Apify免费额度，大规模使用需付费。正式部署时应自建采集层或接入X官方API
2. **互动率算法**：按粉丝数计算互动率，未考虑曝光量（需X Analytics后台数据），可能与实际触达有偏差
3. **驱动因素判断**：基于有限样本（TOP5 vs BOTTOM5）的对比分析，统计显著性有限
4. **相似度检查**：使用文本相似度算法，对语义层面的抄袭判断能力有限
5. **反馈闭环**：当前版本支持资产库记录，但需手动录入发布后表现数据，尚未实现自动追踪

---

## 七、如有更多时间会如何优化

1. **接入X官方API**：实现全自动数据采集，获取曝光量数据改用按曝光量计算互动率，消除对第三方服务的依赖
2. **扩大样本量**：从TOP5/BOTTOM5扩大到TOP20/BOTTOM20，提升驱动因素分析的统计显著性
3. **多账号横向对比**：支持同时分析多个同类账号，交叉验证驱动因素的普适性
4. **自动反馈闭环**：接入发布API，自动追踪候选内容发布后的表现，验证拆解结论
5. **多模态分析**：分析推文中的图片、视频内容，不只看文字
6. **A/B测试框架**：同一主题生成多个版本，自动追踪哪个版本表现更好，持续优化模板

## 九、运行方式

### 环境准备
```bash
pip install -r requirements.txt
```

### 配置API Key
在项目根目录创建 `.env` 文件：
```
SENSENOVA_API_KEY=你的日日新API Key
APIFY_API_TOKEN=你的Apify Token（可选，仅自动采集模式需要）
```

### 启动应用
```bash
streamlit run app.py
```

浏览器打开 `http://localhost:8501` 即可使用。

### 使用流程
1. 在输入框输入X账号用户名（如 `AndrewYng`）
2. 点击"开始分析"，等待数据采集和处理
3. 查看拆解报告、驱动因素分析、内容模板
4. 审核3条候选内容，可编辑修改
5. 点击"确认写入资产库"保存结果
